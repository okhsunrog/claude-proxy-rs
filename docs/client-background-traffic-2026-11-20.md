# Фоновые соединения локального клиента: проверка 20 ноября 2026

## Объект и границы проверки

Проверен установленный Linux x64 Claude Code 2.1.326, SHA-256 бинарника:
`b6b3647d981130dc44fc670846ae97b6cde531ffb667cf9c4d17cfcafb38cb37`.
Это отдельная проверка локального клиента; она не меняет эталон macOS 2.1.326
для исходящего inference-транспорта прокси.

Запуски выполнялись через `unshare --user --map-root-user --net` с поднятым
только loopback. Внутри работал локальный HTTP CONNECT/TLS mock, который
терминировал все запросы и никогда не пересылал их наружу. `strace` фиксировал
соединения, а в последнем прогоне также запуск дочерних команд. Для модельных
запросов mock возвращал фиксированный SSE-ответ `OK`. Использовались тестовые
ключи, пустой рабочий каталог и изолированные конфигурационные каталоги.

Сравнивались режим `-p` и интерактивный запуск без отправки пользовательского
сообщения. Полный интерактивный запуск проверен с заполненным onboarding-state;
ранние запуски, остановившиеся на onboarding, не доказывают поведение сессии.
В последнем прогоне скопированы текущие пользовательские настройки; заменён
только TMPDIR и подставлен тестовый MY_AI_PROXY. Список установленных marketplace
из настоящего пользовательского каталога не копировался.

Ни один модельный запрос не ушёл в настоящий upstream. Дополнительный OAuth
контроль использовал синтетические credentials и mock profile, а не реальную
подписку. Исчерпанный лимит аккаунта не влияет на результаты этого стенда.

## Наблюдения

| Конфигурация | Наблюдавшиеся обращения |
| --- | --- |
| Адрес прокси и bearer token, без privacy-переменных, `-p` | Модельный запрос к адресу прокси; напрямую к `api.anthropic.com`: GET `/api/directory/server-urls` и POST `/api/event_logging/v2/batch` |
| Только `DISABLE_TELEMETRY=1`, `-p` | Модельный запрос и справочник MCP; отправки событий нет |
| Только `DISABLE_ERROR_REPORTING=1`, `-p` | Модельный запрос, справочник MCP и отправка событий; этот флаг не отключает продуктовую аналитику |
| `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, `-p` | Только модельный запрос к локально перехваченному адресу прокси |
| Четыре точечных opt-out из README, через settings, `-p` | Модельный запрос и справочник MCP; отправки событий нет |
| Те же settings, полный интерактивный запуск | Нет отправки событий; остаются changelog на `raw.githubusercontent.com`, справочник MCP, официальный marketplace на `downloads.claude.ai` и установки дополнительных marketplace через GitHub |
| Общий выключатель плюс запрет автоустановки официального marketplace, интерактивно | Остаются попытки установки четырёх marketplace, явно перечисленных в пользовательских `extraKnownMarketplaces` |

В первом headless-прогоне пакет содержал 89 событий, около 156 КБ JSON после
распаковки. Это размер конкретного запуска, а не постоянная норма. Захвачены
`device_id`, `session_id`, время, модель, версия клиента, сведения об окружении,
метрики процесса и поля событий. Окружение включало `platform: linux`, `arch: x64`,
NixOS, версию дистрибутива и ядра, runtime и терминал. У отдельных событий были
корневые `skill_name`, `plugin_name`, `marketplace_name`; это не проверка утечки
имени частного плагина, поскольку такой плагин специально не создавался.

Поле `process` кодирует в base64 JSON со счётчиками памяти/CPU/uptime. Его нельзя
называть дампом содержимого памяти процесса. В синтетическом gateway-сеансе не
было реального email или OAuth account UUID.

Datadog и `/api/claude_code/metrics` в этих прогонах не наблюдались. Это не
доказательство отсутствия таких каналов в других режимах: бинарник содержит
соответствующие реализации и дополнительные условия их включения.

В отладочном журнале полного интерактивного запуска подтверждены фоновые
установки четырёх записей `extraKnownMarketplaces`, хотя все пользовательские
плагины выключены. Наличие marketplace и включение его плагинов — разные
настройки. В свежем каталоге установки выполнялись заново; на обычном профиле
с существующим кэшем последовательность и число запросов могут отличаться.
Mock возвращал заглушки вместо настоящих архивов, поэтому ошибки архивов и
fallback-попытки GitHub не являются дефектом настоящего сервиса.

## Проверенные условия в бинарнике

В извлечённом JS функция `yOn()` выбирает `essential-traffic` при непустом
`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`, `no-telemetry` при непустом
`DISABLE_TELEMETRY` или true в `DO_NOT_TRACK`; иначе `default`. `ht()` проверяет
первый режим, `TC()` — любой opt-out. Поэтому оба значения `"0"` и `"false"`
для первых двух переменных всё равно отключают соответствующий трафик.

В функции загрузки `/api/directory/server-urls` есть ранний выход по `ht()`.
Это согласуется с наблюдением: отдельный запрет телеметрии сохраняет этот GET,
общий выключатель убирает его. Загрузка справочника использует `auth: "none"`.
У обработки ошибок отдельно проверяются `DISABLE_ERROR_REPORTING` и общий
режим; инициализация репортера содержит дополнительные ограничения провайдера
и типа авторизации. Одна найденная строка URL не доказывает отправку запроса.

`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` не является сетевым firewall.
Официальная документация отдельно исключает из него WebFetch domain preflight
и автоустановку официального marketplace. Настройки инструментов/хуков/MCP и
намеренно запущенные пользователем сетевые операции рассматриваются отдельно.
WebSearch/WebFetch этой работой не отключались.

## Обычная команда claude

В пользовательские settings добавлены адрес прокси, `apiKeyHelper`, пустые
`ANTHROPIC_API_KEY`/`ANTHROPIC_AUTH_TOKEN` и четыре точечных opt-out из README.
Ключ берётся из экспортированного `MY_AI_PROXY`, его значение в JSON не сохранено.
Существующий `DISABLE_AUTOUPDATER=1` сохранён, общий выключатель не добавлен.
Существующие настройки памяти, инструментов, интеграций и marketplace сохранены.

Mock подтвердил, что при старте без адреса/ключа в командной строке адрес берётся
из settings, а оба заголовка `x-api-key` и `Authorization: Bearer` содержат
значение helper. Для проверки приоритетов во входное окружение специально
передавались другие тестовые `ANTHROPIC_API_KEY` и `ANTHROPIC_AUTH_TOKEN`:
пустые значения в settings не дали им переопределить helper.

Дополнительно настоящий `claude auth status --json` с текущими settings запущен
в изолированной сети: `loggedIn: true`, `authMethod: api_key_helper`,
`apiKeySource: apiKeyHelper`. Поле `apiProvider: firstParty` обозначает ветку
API клиента и само по себе не доказывает прямое соединение с Anthropic.
Настоящий inference через публичный прокси после переноса настроек не вызывался.

Старое имя `claude-proxy` оставлено как функция, передающая аргументы обычному
`claude`; дополнительной настройки подключения в ней больше нет. Для нового
запуска `claude` перечитывать `.bashrc` не требуется. Ранее запущенные процессы
не были перезапущены и не входят в эту проверку новых startup-настроек.
